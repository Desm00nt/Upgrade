# Статус проверки

Дата: **21 сентября 2026**.

## Выполнено

- Независимый модуль `core` скомпилирован для **Java 17** компилятором **ECJ 3.33.0**.
- **Пройден 121 тест JUnit**, 0 пропущено, 0 ошибок.
- Запуск: OpenJDK **17.0.9**, JUnit Platform Console **1.10.2** / Jupiter **5.10.2**, Gson **2.10.1**. Хеши скачанных для проверки ECJ, Gson и JUnit сверены с опубликованными хешами Maven Central.
- Проверены строгий разбор ответа, булевый флаг награды, фильтрация/ограничение текста, безопасные настройки endpoint, отсутствие секретов в диагностике, разделение/вытеснение/срок жизни диалогов, роль пользовательского текста, минимальное число реплик и глобальные/индивидуальные лимиты.
- На настоящем локальном HTTP-сервере-моке проверены UTF-8, Authorization, модель и формат запросов; HTTP-ошибки, отсутствие автоматических повторов, запрет редиректов, лимит тела 128 KiB, дедлайн после получения заголовков и отмена запроса через interrupt.
- Добавлены и проверены сценарии настройки ключа: нормализация/отказ некорректному токену, запрет без авторизации, приоритет окружения, сохранение до активации, ошибки сохранения/активации без раскрытия секрета, удаление ключа и неизменяемые снимки настроек. Локальный HTTP-мок подтверждает, что тот же клиент отправляет новый Authorization после ротации ключа.
- В проект включены Gradle Wrapper 8.8 с контрольной суммой дистрибутива, полноценный ForgeGradle-проект и workflow сборки GitHub Actions.

## Не выполнено в этой среде

- **Полная Forge-сборка и reobfJar не завершены.** Из sandbox не устанавливается TLS-соединение с `services.gradle.org` / `downloads.gradle.org`, Maven Central, Forge Maven и серверами загрузки Minecraft. `./gradlew -p core test` и `./gradlew build` останавливаются уже при скачивании Gradle с `SSLHandshakeException`. Поэтому core-тесты были скомпилированы и запущены непосредственно через ECJ и JUnit Console, а не через Gradle.
- **Готовый установочный JAR не выдаётся за собранный.** Путь `build/libs/kustik-1.20.1-1.0.0.jar` в README — результат будущей успешной полной сборки, не существующий здесь артефакт.
- `KustikRewardsTest` (NBT/SavedData) и `KustikConfigTest` (реальный Forge/NightConfig: сохранение/удаление ключа в TOML, отказ до загрузки конфига, сохранение остальных настроек при горячей смене ключа) включены в полную сборку, но **пока не запускались**: им нужен полный Forge-класс-путь. Они не входят в число 121 пройденного core-теста.
- Регистрация команд, проверка владельца/OP, отсутствие обхода через `/execute as` и отмена ожидающих ответов при смене ключа требуют игрового прогона из `TESTING.md`. Core-тесты не заменяют этот прогон.
- Minecraft-клиент и выделенный Forge-сервер в этой среде **не запускались**. Игровые сценарии находятся в [TESTING.md](TESTING.md).
- **Живой Atria API не вызывался:** пользовательский ключ не предоставлялся и не запрашивался в чате. Протокол реализован по официальной документации и проверен на моке, а не на настоящей модели. Реальные задержки, формат ответа модели и качество ролевого диалога нужно проверить со своим ключом.
- Workflow подготовлен, но **удалённый запуск GitHub Actions не выполнялся**.

## Как воспроизвести обычным способом

На машине с **JDK 17** и доступом к серверам зависимостей:

```bash
./gradlew -p core test
./gradlew build
```

На Windows — `gradlew.bat` вместо `./gradlew`.

Отчёты: `core/build/reports/tests/test/index.html` и `build/reports/tests/test/index.html`. Затем выполнить ручной игровой чек-лист. Внешний API не нужен для автоматических тестов; ключ нужен только для проверки живого разговора.
