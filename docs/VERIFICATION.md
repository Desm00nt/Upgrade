### Проверка самого JAR на CI

Задача `verifyModJar`, обязательная для `build`, запускается **после `reobfJar`**. Она открывает готовый файл из `build/libs`, проверяет:

- версию мода и диапазон Forge в упакованном `META-INF/mods.toml`;
- отсутствие нераскрытых `${...}` в метаданных;
- наличие основного класса мода, `ApiKeyManager` и ресурса `kustik/bush-system.txt`.

Проверка прошла. В annotations успешного job есть **Kustik JAR verified** с именем файла, диапазоном Forge и SHA-256. Контрольная сумма **самого JAR, не скачиваемого ZIP**:

```text
26dc2dd6dd92ec01cd41eb895f0db10deeb324aa701a4b1dadc9c92f693fd898
```

В этой среде скачивание бинарного артефакта и полных логов с хранилища GitHub заканчивается сетевым EOF. Поэтому JAR проверялся непосредственно на GitHub runner, а результат подтверждён через API check annotations. Артефакт существует, не истёк и доступен по ссылке выше через браузер GitHub. Локальный JAR в sandbox не выдаётся за скачанный.

## Автоматические тесты

- Независимый модуль `core` ранее прошёл **121 тест** на Java 17; в новой CI-сборке его Gradle-тесты также прошли успешно.
- Проверяются HTTP-протокол Atria на локальном mock-сервере, Authorization/UTF-8, ошибки API, запрет редиректов, отмена, дедлайн чтения тела и лимит ответа.
- Проверяются строгий JSON-ответ, флаг награды, очистка текста, память диалогов, лимиты, правила выдачи палки и безопасная смена API-ключа.
- В полной Forge-сборке прошли также `KustikRewardsTest` (реальный NBT/SavedData), `KustikConfigTest` (Forge/NightConfig и сохранение ключа) и `KustikMetadataTest` (сгенерированный дескриптор принимает Forge 47.4.0).

## Что ещё не проверено

- Minecraft-клиент и выделенный сервер **не запускались для игрового прогона**. Успешная сборка/тесты не заменяют проверку взаимодействия в живом мире.
- Живой Atria API **не вызывался**: собственный API-ключ нужно настроить у себя. Мок проверяет протокол, а не поведение настоящей модели, реальные задержки или качество убеждения.
- Игровые сценарии, включая права владельца/OP, отмену ожидания при смене ключа и выдачу палки, перечислены в [TESTING.md](TESTING.md).

## Как воспроизвести

На машине с **JDK 17** и доступом к серверам зависимостей:

```bash
./gradlew -p core test
./gradlew build
```

На Windows — `gradlew.bat` вместо `./gradlew`.

Локальные HTML-отчёты: `core/build/reports/tests/test/index.html` и `build/reports/tests/test/index.html`. Текущий workflow публикует артефакт с JAR; HTML-отчёты отдельно не загружаются.

При обновлении убери старый `kustik-1.20.1-1.0.0.jar` из `mods` и положи новый JAR. `config/kustik-common.toml` и файлы мира оставь на месте — менять Forge 47.4.0 на другую версию для этого исправления не требуется.
