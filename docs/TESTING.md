# Проверка в Minecraft

Эти сценарии — чек-лист для реальной игры. Наличие списка не означает, что прогон уже выполнен; текущие результаты записаны в [VERIFICATION.md](VERIFICATION.md).

## Подготовка

1. JDK 17, Minecraft Java 1.20.1, Forge 47.4.10+ (47.x).
2. `./gradlew build`, затем установи **только** `build/libs/kustik-1.20.1-1.0.0.jar` в `mods`.
3. Используй отдельный тестовый мир и сохрани резервную копию. Не проверяй новые моды на единственной копии важного мира.
4. Сначала зайди **без API-ключа**: мир должен загрузиться, `/кустик` — показать справку. `/kustikadmin status` в консоли должен сообщить «ключ не настроен», не раскрывая настройки.
5. При желании включи читы только в тестовом мире и поставь сухой куст на песок:
   ```text
   /setblock ~2 ~-1 ~ minecraft:sand
   /setblock ~2 ~ ~ minecraft:dead_bush
   ```
6. Для живого API настрой ключ через `/кустикключ <API-ключ>` (применяется сразу) либо локальный конфиг/окружение (требует переоткрыть мир/перезапустить сервер). Реальные разговоры расходуют квоту Atria; команда настройки сама запрос не делает.

## Команды и поиск

- `/кустик` и `/kustik` доступны обычному игроку без OP.
- Сообщение без фигурных скобок, с пробелами и кириллицей целиком попадает в диалог.
- Вне радиуса, за сплошной стеной, около травы, в режиме наблюдателя — понятный отказ **до HTTP-запроса**.
- При двух кустах отвечает ближайший видимый. После перехода к другому начинается отдельный диалог.
- Консоль не может вести разговор; `/kustikadmin status` в консоли работает.
- Проверка Minecraft-команд выполняется сервером, без клиентских GUI/собственных пакетов.

## Команда настройки ключа

Используй вымышленные токены для проверки сохранения, прав и ошибок; настоящий ключ нужен только для живого API.

- Владелец одиночного мира **с выключенными читами** видит `/кустикключ` и `/kustikadmin key`, может сохранить ключ. Гость LAN без OP — нет.
- На выделенном сервере OP 0–3 и командные блоки не могут менять ключ. OP 4 и консоль — могут. `/kustikadmin status` доступен OP 2 и владельцу одиночного мира, но не показывает значение ключа.
- На LAN-сервере гость с OP 2 не должен получить права владельца через `/execute as <владелец> run кустикключ <вымышленный-ключ>`: проверяется **исходный отправитель**, а не подставленная сущность.
- `/кустикключ` и `/kustikadmin key` без аргумента показывают справку, ничего не удаляют.
- Ключ с пробелом внутри, кавычками или управляющими символами отвергается фиксированной ошибкой. Значение не должно появляться в ответе мода, автодополнении или AI-истории. Внешняя история команд/логи вне контроля мода.
- После `/кустикключ <вымышленный-ключ>` проверь `atria.apiKey` в `config/kustik-common.toml`: значение сохранено, другие настройки не меняются. `/kustikadmin status` сразу показывает «ключ настроен», без перезапуска. Это не означает, что вымышленный ключ примет Atria.
- С настоящим ключом следующий диалог отправляет новый Bearer-токен. Смена ключа не очищает диалоги, не сбрасывает минутный бюджет и не восстанавливает палки.
- Смени ключ **во время ожидающего ответа**: запрос отменён, игрок получает уведомление, поздний ответ со старым ключом не выдаёт награду и не дописывает историю. Следующая попытка использует новый ключ.
- `/kustikadmin clearkey` очищает сохранённое значение, отменяет ожидание и отключает новые HTTP-запросы. После перезапуска ключ не восстанавливается, если нет переменной окружения. Команда не отзывает токен в Atria и не очищает старые копии/историю ввода.
- При непустом `ATRIA_API_KEY` обе команды изменения отказывают без изменения файла/активного подключения. Статус не раскрывает ключ из окружения.
- На копии тестового профиля запрети запись конфига. Команда должна сообщить об ошибке сохранения без токена/stack trace в ответе, активное подключение остаётся прежним. Верни права на запись и проверь содержимое файла.
- Второй оператор не получает уведомление с командой или значением: сообщения отправляются только вызвавшему команду. Игроки с отменёнными ожиданиями видят лишь уведомление об изменении подключения.

## Реальная Atria и награда

- Вежливо представься, затем объясни нужду в палке. Ответ — личный, по-русски, от имени кустика; последовательные реплики учитывают контекст.
- Первое сообщение при `minimumTurns=2` не даёт палку даже при согласии модели.
- Когда модель действительно соглашается: в выживании добавляется **ровно 1 палка**, показывается подтверждение и частицы.
- Повторное убеждение в том же месте не даёт вторую палку. Диалог при этом продолжается.
- Выход/вход, нормальное сохранение и перезапуск, смена измерения и возвращение, поломка/посадка куста в тех же координатах не сбрасывают награду.
- У второго игрока независимый разговор и одна собственная награда. Другой куст или измерение также имеют отдельное ограничение.
- Полный инвентарь без места для палки: одна палка выпадает рядом; повторного начисления нет. Если другой мод отменяет выпадение, ограничение не должно считаться использованным без успешной выдачи.
- Заполни все слоты, но оставь неполный стак палок: награда должна пополнить этот стак.
- Обычное разрушение куста не изменено: ванильный дроп не является наградой за разговор.

## Асинхронность и отмена

Пока видно «Кустик шуршит веточками…»:

- Отправь вторую команду: не должно быть второго HTTP-запроса от этого игрока.
- Продолжай играть: мир и другие игроки не должны ждать HTTP-ответа в игровом потоке.
- Уйди дальше радиуса, переместись в другое измерение, умри или поставь стену. При возвращении ответа не должно быть награды, если условия больше не выполнены.
- Сломай куст игроком: ожидающий ответ отменяется. Быстрая повторная посадка не оживляет старый запрос.
- Выйди и зайди с тем же UUID: старый callback не выдаёт награду новому подключению.
- Останови сервер или выйди в меню одиночной игры. Не должно оставаться потоков, которые держат процесс или меняют уже закрытый мир.
- После возвращения в **другой** мир нет истории/ограничений от предыдущего мира.

## Ошибки API и ограничения

Автотесты с mock HTTP проверяют 401/403, 429, 400, 5xx, редирект, некорректный JSON, обрыв/ограничение генерации, размер ответа, отмену и таймаут чтения тела. В игре дополнительно проверь:

- Неверный ключ — короткая ошибка, без API-ключа, сырого тела ответа и stack trace в чате/логе мода.
- Отключение сети — сервер остаётся отзывчивым; по дедлайну игрок получает ошибку.
- После ошибки можно повторить попытку; неверный ответ не добавляет историю и не выдаёт предмет.
- Снизь `requestsPerMinute` до 2 и перезапусти мир. Несколько игроков не должны обойти общий лимит.
- Частые команды и выход/вход не обходят короткую паузу игрока.
- Модель, вернувшая текст `/give ...` или Minecraft JSON-компонент, не должна вызвать выполнение команды/кликабельное действие. Это обычный текст.

## Мультиплеер и секреты

1. Мод стоит только на выделенном Forge-сервере. Подключись совместимым клиентом без этого мода.
2. Убедись, что сервер не требует установки `kustik` клиенту и что команды доступны.
3. Два игрока беседуют с одним кустом: ответы и история не смешиваются, сообщения не рассылаются всему серверу.
4. Клиент не получает серверный `kustik-common.toml`/API-ключ. Не использовать `ModConfig.Type.SERVER` для ключей.
5. На клиенте с установленным модом можно подключаться к серверу без него; локальная установка не должна выдавать себя за серверную интеграцию.
